# 个人自用好感度插件

一个面向 MaiBot / Maisaka 的个人好感度与分级相处方式插件。按真实 QQ 账号保存关系，支持保守自动评分、手动授权、WebUI 管理，以及规划器和回复器的关系提示。

> 个人自用项目，欢迎按自己的角色风格修改。它通过宿主 Hook 注入上下文，不替换模型，也不保证模型每次都按提示表现。

不完善的内容：
好感度增减公式相对简陋，主要依靠手动调整
通过上下文约束来调整的回复，而非完全掌控规划器

作者：[TreadingonFrost](https://github.com/TreadingonFrost) · MIT License

## 它解决什么问题

让机器人面对不同的人，有不同的熟悉程度和相处方式。基础人格继续定义角色本身；每个关系等级的“额外设定”补充面对当前对象的称呼、距离和表达习惯。群聊和私聊共用一份分级设定，可选择是否在群聊显示高阶关系。

插件不是“聊天越多越自动亲密”。普通刷屏、单句粗话或熟人互损不会天然获得加分或扣分；评分有冷却、每日预算、次数限制和消息去重。

## 主要功能

- **八个有效等级**：−2 反感、−1 疏远、0 普通、1 熟悉、2 友人、3 亲切、4 亲密、5 管理员。文案可在配置页修改。
- **积分与授权分开**：30 / 70 / 100 / 150 分对应积分档 1 / 2 / 3 / 4；负向 −30 / −70 对应 −1 / −2。自动有效等级最高 2，3 / 4 仍须手动授权。普通积分范围 −200～200。
- **唯一管理员**：由部署者填写账号，固定 200 分、有效等级 5，不能通过聊天刷取，也不能把 5 级授予别人。公开包不预填真实账号。
- **WebUI 管理**：查询单个数字 QQ、调整积分、授予或撤销 3 / 4 级，显示积分档和有效等级；写操作校验版本并记录审计。
- **群私一致**：同一等级使用同一份额外设定；群聊默认投影最高 2 级，可开启 3 / 4 / 5 级表现。群聊提示不带私密分数、授权来源或审计。
- **规划层关系提示**：根据近期真实消息，为规划器提供逐对象的关系和额外设定，不能把最近一个人的关系套给全群。
- **回复层精准注入**：根据本轮实际回复消息重新确认对象，再注入其关系设定；昵称、引用和正文自称不决定身份。
- **暂停与语气预览**：支持本人私聊暂停 / 恢复关系互动，以及管理员临时预览等级语气。

## 规划器和回复器到底怎么分工

这是本插件的重要设计，而不是宣称“好感度完全接管模型”。

1. **规划器决定行动**：是否参与、回复哪条消息、需要什么工具。它获得有真实消息 ID 和作者账号的关系提示。
2. **基础人格和关系设定决定表达**：角色是谁、面对这个人有多亲近、如何说话，由基础人格与该对象的额外设定共同约束。
3. **回复器组织具体语言**：规划器提供的回复参考是可选话题线索，不应写成必须照演的台词、固定笑点或“先骂后软”的脚本。

插件通过 `maisaka.planner.before_request` 和 `maisaka.replyer.before_request` 接入。规划器仍有工具选择权，注入内容属于模型上下文约束，不是确定性授权机制。宿主自身的系统提示和回复工具契约若强制规划器代写台词，也需要调整宿主；单独安装插件不会替别人改写 MaiBot 核心文件。具体接入点与可选调整见 [规划器接入说明](docs/planner-integration.md)。

本插件不附带图片、图库、发图工具或任何个人角色素材。它可影响模型对工具的选择倾向，但实际图片检索、发送和去重由相应工具插件负责。

## 兼容范围

当前按 **MaiBot 1.3.19、插件 SDK 2.21.0、Maisaka 聊天链路**整理和验证。其他版本请先确认 Hook 名称、Context Item schema 和 WebUI 能力契约，不承诺直接兼容。Python 和 Pydantic 由宿主环境提供；核心状态层仅使用标准库。

## 安装与初次配置

1. 下载仓库：页面绿色 **Code** → **Download ZIP**，解压。
2. 把包含 `_manifest.json` 和 `plugin.py` 的整个目录放进 MaiBot 的 `plugins` 目录。不要重复嵌套两层，也不要上传或覆盖自己的关系数据库。
3. 在 MaiBot 插件管理中加载插件，打开配置页。发布模板默认关闭，自动评分默认关闭。
4. 填写机器人实际 QQ 账号、连接域 `scope` 和唯一管理员 QQ。机器人账号与管理员账号是两个概念，不要填反。账号和 scope 必须与宿主收到的真实消息路由一致。
5. 按需修改各等级的“额外设定”，保存后启用。需要自动评分时，再把 `evaluation_mode` 设为 `automatic`；它复用宿主模型任务，会产生模型调用费用。
6. 好感管理页面中先输入数字 QQ 并查询，再调整积分或授权。不要根据昵称修改对象。

默认配置示例见 [config.default.toml](config.default.toml)。这是无个人信息模板，不包含真实机器人、管理员或群号。

## 私聊命令

```text
/relation status
/relation grant3 <数字QQ>
/relation grant4 <数字QQ>
/relation revoke <数字QQ>
/relation setscore <数字QQ> <分数>
/relation preview <等级>
/relation reset_styles
/关系暂停
/关系恢复
```

普通用户只能查看本人状态及控制本人的暂停 / 恢复。授权、设分、预览和重置由配置的唯一管理员在经过身份核验的私聊中使用。`revoke` 只撤销手动高阶授权，不清空积分。暂停和预览是运行内存状态，重启后不保留，不代表强制中断整台机器人发送。

## 数据与隐私

关系数据保存在插件数据目录的本地 SQLite 文件中，按平台、机器人账号和 scope 分库。插件保存积分、授权、计数与必要审计，不把聊天正文当作自由文本关系笔记存储。SQLite 不是加密数据库，应自行保护机器和文件访问权限。

自动评分会把必要的消息内容交给你在宿主中配置的模型服务。群聊公开投影不等于对整个模型上下文的隐私保证；其他宿主模块或插件仍可能注入自己的资料。

仓库不包含真实配置、QQ 关系库、聊天记录、运行日志、备份、密钥或访问令牌。不要把 `config.toml`、`data/`、`logs/`、`config_back/` 或旧 `.git` 历史上传。详见 [隐私说明](PRIVACY.md)。

## 测试

在宿主的 Python 环境中，从插件目录运行：

```text
python -B -m unittest discover -s tests -v
```

测试使用临时数据库和模拟 SDK，不向 QQ 发消息。涉及 SDK 的集成测试需能导入宿主安装的 `maibot_plugin_sdk`。项目不通过测试替用户发送真实消息，也不在导入时读取历史关系库。
